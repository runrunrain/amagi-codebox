# 分级归并与修复策略

## 定级规则（同根因合并后，就高不就低）

| 级别 | 定义 | 典型来源 |
|---|---|---|
| P0 | 可被利用的安全漏洞；确定会改变运行时行为的正确性 bug | govulncheck 中/高危且 call-stack 可达；staticcheck SA\* 中影响控制流/数据正确性的（如 SA5003 defers 无效、SA4006 与 ineffassign 重叠时看上下文） |
| P1 | 缺陷风险——特定输入/时序下会出错 | errcheck 未检错误（尤其写路径、外部进程、文件操作）；ineffassign 无效赋值；SA\* 中边界类（SA1015、SA6005 等）；govulncheck 低危且可达 |
| P2 | 死代码与清理——不影响行为 | unused（未用函数/类型/字段）；knip 未用导出/文件/依赖；注释掉的代码块 |
| P3 | 风格与低收益 | ST\*/QF\*（仓库已明确排除，**不要修**）；格式化差异 |

去重规则：govet 与 staticcheck 的 SA\* 有少量重叠，同一文件同一行只报一条，来源标注两个工具。

## 合并规则

同一根因的多个命中合并为一项。判断标准：改一处代码能否同时消除这些命中。

- 同一函数里 3 处 errcheck → 一项（"该函数错误路径未处理"）
- 同一依赖在 5 个文件的 unused 导入 → 一项
- govulncheck 同一依赖的多个漏洞 ID → 一项（一次升级解决）

## 误报甄别清单（命中以下情形时降级为"跳过"并注明原因）

1. **Wails 绑定**：导出的 App 方法即使看似无 Go 侧调用方，也是前端调用入口，不能按 unused 删除。
2. **构建标签**：`//go:build windows` / `!windows` 门控的分支在另一平台"未使用"，不是死代码。
3. **测试夹具与 e2e**：`e2e/`、`*_test.go` 里被测试引用的导出不算 unused。
4. **动态引用**：通过反射、插件名、字符串拼接调用的符号，静态工具看不见。
5. **根目录 `*.test` 文件**：本地遗留测试二进制，非源码。
6. **knip 对 `wailsjs/`、`dist/` 的所有命中**。

## 修复策略（按级别）

### P0
- govulncheck 命中：升级依赖到修复版本。升级属于独立改动，先单独列出征询用户，不与代码修复混在一个 commit。
- SA\* 正确性 bug：先写复现测试（失败态）→ 最小修复 → 测试转绿。禁止"顺手重构"周围代码。

### P1
- errcheck：先查 `.golangci.yml` 的 exclude-functions——清理惯例（defer Close、best-effort Remove 等）不该硬修；其余按语义处理：
  - 可忽略 → `//nolint:errcheck // 理由`
  - 该上抛 → 上抛或记日志，遵循该文件既有的错误处理风格
- ineffassign：删除无效赋值或修正赋值目标，通常是逻辑笔误的线索，先看上下文再动手。

### P2
- 删除前过一遍上面的误报甄别清单。
- 未用依赖卸载（`go mod tidy` / `npm uninstall`）单独成项，因为会动 lockfile。
- 删除量大的（>100 行）先给用户看清单再动手。

### P3
默认不做。用户坚持要做时提醒：`.golangci.yml` 注释里已记录排除 ST\*/QF\* 的决策原因（ST1005 会改用户可见文案、ST1008 会改既有清理闭包签名等），翻案需要更新那段注释。
