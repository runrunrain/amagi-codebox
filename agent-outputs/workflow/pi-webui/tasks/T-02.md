## 目标（可验收）

在 amagi 扩展进程内实现并验证最小 webui server：绑定 127.0.0.1:<port>，提供 GET /api/info（返回 sessionId 等元信息）与 WS /ws/events（透传 pi 会话事件），在真实 pi 会话中验证 WS 客户端能收到 message_update 等事件流。

## 实现要求

1. spike 代码放 worktree 内 `extensions/amagi-core/webui-spike/`（独立目录，不并入主模块结构）；作为扩展被 pi 加载（可临时注册或复用 amagi-core 入口的开发开关，禁止改 settings.json）。
2. **加载机制本身是 spike 验证点**：调查并记录如何在不动 `~/.pi/agent/settings.json` 的前提下让 pi 加载本扩展（候选：pi CLI 的 package/extension 临时参数、PI_HOME 环境变量、`--config` 类覆盖；读 packages.md/cli 文档求证）。若所有路径都要求写 settings，允许用"备份→临时加行→验证→立即还原"方式并在报告记录，但绝不留下持久修改。
3. HTTP server 用 node:http；WS 可临时 `npm i ws --no-save`（不落 package.json；若 jiti/打包环境不允许新依赖，手写最小 RFC6455 帧或改用 SSE 并在报告中说明对契约 TD-3 的影响建议）。
4. 事件订阅至少覆盖：session/message/message_update/tool_execution_update；信封格式按技术方案 §5（v:1, seq 单调, kind, event 原样透传）。
5. 会话内验证：运行一个真实 pi 会话（最小成本：单轮短 prompt，如"回复 ok 即可"），用 `wscat`/curl/自写 node 客户端连接并记录收到的事件 JSON 片段。
