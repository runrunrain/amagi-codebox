## 目标（可验收）

回答一个问题并给出证据：**运行中的 pi TUI 会话，能否从 amagi 扩展（同进程）向该会话注入用户输入（新 prompt 或 steer），使模型轮次被触发且 TUI 平面同步可见？** 输出 M2 档位建议（可行/条件可行/不可行）。

## 验证路径（按优先级，全部求证后下结论）

1. **扩展 ctx 直达**：extensions.md / dist 类型声明里查 ExtensionAPI 是否暴露 agent session 或 prompt/steer/inject 类方法；有则最小 demo 验证（扩展内调用 → TUI 出现该轮次）。
2. **事件反推**：amagi-core 的 input 路由订阅能拿到什么（只读事件 or 可拦截/合成？）。
3. **RPC 旁路**（若 1/2 不可达）：`pi --mode rpc` 子进程 switch_session 到同一会话文件后 prompt——注意调研 02/04 的结论：resume 是新进程重放，双进程写同一 JSONL 语义未证实；若走此路必须实测"原 TUI 进程继续写、RPC 进程同时写"是否损坏会话文件，损坏即判该路不可行。
4. 若全部路径反证：结论"不可行"，附每条路径的反证证据（API 不存在/能力拒/文件损坏样本）。
